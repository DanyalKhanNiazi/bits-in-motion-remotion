# Episode 06: creative direction (read this first)

**Film:** "Why Deleting a File Doesn't Erase It". 567.432 s, **17,023 frames** at 30 fps, 1920×1080.

**Brief:** build the whole picture as code, in the channel's **Signal Atlas** style, to the standard of the Ep03 rebuild (83.6 on the rubric) or better. Never repeat: slideshow holds, dips to an empty stage, small "ledger-speak" labels, flat sticker props, one navy room for ten minutes, a metaphor that is never built, numbers that disagree with the voice.

This version folds in three independent critiques (accuracy, engagement, production). Where this file is more specific than the playbook, this file wins.

## 1. Locked, never change
- **The narration.** The truth for wording and sync is `docs/ep06/TRANSCRIPT.md` (word@absoluteFrame). Clock helpers in `src/ep06/timing.ts`: `at(paragraph, 'phrase', nth?)` → `{start, end}` absolute frames; `P(n)`; `TOTAL = 17023`.
- **Section bounds are half-open `[from, to)`** (`src/ep06/sections.ts`). Tools take inclusive ranges: `--frames from-(to−1)`, queue `S#:from-(to−1)`.
- **Transcription quirk:** the SRT writes "cypher" (P21); on screen always write **cipher**. The SRT writes "2011" and "16" as digits; fine on screen.
- **Accuracy guardrails:** `docs/ep06/script_editorial.md` (§A scope and term budget, §D key visual beats V1–V11 and their "Limitation" column, §E claim ledger C00–C26). **This topic is accuracy-sensitive.**

### 1.1 Numbers
- On-screen numbers are spoken numbers, in the spoken form: **2011**, **16 SSDs**, **"at most about a quarter"** (or "at most about ¼ of the blocks"; never "27%", never a hard 25% line), **Shift + Delete**, **cipher /w**.
- The only unspoken digits allowed are **decor box identifiers** (wall, map, TRIM note: MONO, ≤ 24 px on screen, never a claim). No AtlasOpener index number. No digits on any timer or clock (the schedule clock has no numerals or hands pointing at a time). No sizes, dates, times, capacities, percentages or versions anywhere (Explorer, cards, Settings, drives). The card's "directions" are three numberless sockets.

### 1.2 Words (term budget)
- No jargon the voice doesn't say. **Never on screen:** HDD (always write "Hard drive"), garbage collection, wear levelling, over-provisioning, FTL / flash translation layer, controller, RAID, cryptographic erase, 27%, bitmap, $Bitmap, $Recycle.Bin, platter, NAND, M.2, sector, page, erase block, LBA, TPM, at rest, runs, signature, carving, purge, SP 800-88, MFT (write "Master File Table" only from P06).
- Use the voice's words: "housekeeping", "keeps moving data around", "so no part wears out first", "spare space", "labels", "multi-drive arrays", "destroying the key", "map of which boxes are taken". **Before f9553 the amber actor is "the drive"**; only from P14's "the chip that runs the drive" may it be called that.
- A simplification gets a footnote of ≤ 6 words (assigned per section in §8). Footnotes are not must-read and don't count toward the 12-word limit.

### 1.3 Quotes
- Quotation marks go **only** around words that appear verbatim in both the voice and the ledger source (§E); mark omissions with "…". Where the voice paraphrases, use **reported speech without quotation marks**: "Microsoft warns: …", "NIST: …".
- A quote is **never a full-frame card or a hold**. It is an attributed in-world strip (≤ 12 words, above the bottom 140 px) while the mechanism it describes plays underneath. Attribute as the voice does: "Microsoft · Windows File Recovery page", "NIST, the US standards agency". No logos. Exact strings are in §8.

### 1.4 Safety and honesty
- The passport is **fictional**: indistinct silhouette, blank fields, no number, seal or name. Footnote once in the hook: "Fictional example". The only file name ever shown is `passport.jpg`.
- Recreated Windows UI is **generic and dark**: no logos, wallpaper, real icons, username, account, email or avatar; paths read "This PC › Pictures"; the prompt reads `C:\>`; no taskbar clock/date; no size/date/capacity values; other file rows blank; no recovery-key digits (a key icon in a safe only). The PC's own drive only: no USB stick or SD card anywhere in P01–P03.
- The passport scenario is **hypothetical** (C00). The mid-film race is an **illustration, not a test**: footnote it so.
- On-screen advice matches the voice in meaning, word for word where possible (§8 S9). Never suggest wiping a whole drive except P21's "To wipe a whole SSD before it leaves your hands, use the drive maker's sanitize tool", always shown with its scope and never on screen together with "gone for good".
- Encryption is **never** shown converting existing plain Bits into glyphs: it protects only data saved while it was on (§8 S8).

## 2. The spine

### 2.1 The governing metaphor: the Wall and the Drawer (`<Archive>`)
The voice builds it in P04: "a huge wall of numbered storage boxes … a drawer of index cards. The boxes hold the data. The cards say which boxes belong to which file." This is the run brief's "library catalogue" seed in the voice's own words: the **drawer of index cards is the catalogue**, the **wall of boxes is the shelving**.
- **Introduced explicitly** at P04 with the naming beat: AtlasOpener word **"The picture"** + sub-line **"boxes and cards"** (64 px). Parts are labelled only when the voice names them: "File system" + "NTFS" (P05, spanning wall and drawer together), "clusters" (P05), "Master File Table" (P06, the drawer), "Map of which boxes are taken" (P07).
- **One kit component** draws every state of the story, so it looks identical everywhere. Builders never draw their own wall, drawer, card, Bit, split screen or Windows UI.
- Its limit is spoken in P06: a tiny file lives entirely on its card (grey Bits on the card; caption "Fits entirely on its card").

### 2.2 `<Archive>` contract (kit-owned; frozen at the kit gate)
- **Geometry** (framing `wide`, zoom 1, world px): the **Drawer** sits LEFT of the Wall, top-aligned; the **map of taken boxes** sits under the drawer as a 16×9 mini-grid mirroring the wall. **Wall: 16 columns × 9 rows = 144 boxes**, pitch 72 (box 64 + gap 8), numbered **001–144** row-major (3-digit MONO, decor). The wall's edges fade into haze so it reads as part of a far bigger wall. The photo's card, when lifted, rises to a fixed spot above the wall's top-left (framings `split` and `signature` show card + wall without the drawer). SSD only: 2 spare columns (17–18) to the right, hidden until P17. Exported as `ARCHIVE.GEOM`.
- **The photo's boxes (never change): 9 boxes in 3 runs: 021–023, 058–060, 098–100.** Header glyph = a bright cyan notch across the top of 021. Each run is one "directions" socket on the card and one cyan thread fanning to its 3 boxes. Erase-group neighbours 024, 057 and 097 are empty, so an SSD group erase never destroys another file. **P09 hits:** download → 059, update → 099, temporary file → 022.
- **Other files:** one seeded occupancy (`random('ep06-wall')`, ≈ 40 % of the remaining boxes), identical in every section. Their Bits are white/grey (`PAL.tileMid`).
- **Bits:** 4 per box (2×2). The photo's Bits are cyan and breathe (90 f period, absolute frame).
- **The card** (one renderer for the drawer card, close-ups and `<IndexCard>`): layout registered to `mft-record_b`. Field names only: **name** (`passport.jpg`), **size**, **dates** (blank value bars), **directions** (3 sockets, no numbers). Paper `PAL.tile`, ink `PAL.tileInk`. Other cards are blank and ruled, nameless.
- **Card states:** active · struck (8 px coral scratch across the name over 10 f; threads go dashed, because the directions still exist) · free / unused (coral tab on the top edge) · reused (grey scribble over the name, nothing readable; threads snap and fade).
- **Box states:** empty · photo · other · available (dashed outline + hollow corner dot; Bits stay lit) · disposable (amber dashed corner tag) · overwritten (6 f coral ring flash, then grey Bits) · erased (14 f amber edge sweep, then a dark clean interior with a fading amber ember; the frame stays visible so a shot is never empty) · refused (P11 bounce, coral) · stale (cyan Bits in SSD back spots that no label points to) · scrambled (MONO glyphs in `PAL.muted`, reseeded every 3 f; never cyan).
- **Modes:** `hdd` = navy steel bins as in `cluster-wall_b`, a slow platter glow behind (background only; Bits never sit "on the platter"). `ssd` = graphite cells; erase groups of 4 in a row (cols 1–4, 5–8, 9–12, 13–16) outlined like `erase-block-tray_b`; the amber drive actor under the wall's lower-left corner; `layers: 'single'` until P17, then `'split'` (front labels lifted forward, back spots + spare columns, a fixed seeded label→spot map `ARCHIVE.SSD_MAP`). **Before any SSD group is cleared, still-wanted white Bits hop to a fresh spot first.**
- **API:** `<Archive frame mode layers state events />`; `state` = a named preset (§2.3); `events = [{at, op, target, dur}]`, op ∈ build · pour · threads · strike · flag · reuse · mapFlip · readPulse · scan · copyOut · overwrite · trim · tag · sweep · refuse · splitLayers · remap · sanitize · scramble · unscramble · boundary; target ∈ 'photo' · 'free' · 'all' · box ids. State at a frame = preset + every event with `at ≤ frame`.
- **Camera:** `archiveCam(framing)` returns Stage poses for 'wide' · 'wall' · 'drawer' · 'card' · 'photoBoxes' · 'run' · 'header' · 'map' · 'boundary' · 'layers' · 'split' · 'signature' · 'pullout'. Sections pass them to `<Stage cam>` so drift, blur, shake and `screen` text behave as everywhere else.
- **Anchors:** `archiveAnchors(props, frame)` returns world points for card, field.{name,size,dates,directions}, flag, drawer, box(id), photo[9], runs[3], header, map, mapCell(id), slot, actor, spare, platter, plus `pxPerBox`.
- **Ambient motion is built in** (Bit breath, platter glow spin, haze dust, a 2 px card float) and driven by the absolute frame, so cuts between sections never jump.
- `<Archive>` draws **no must-read text**. Box and TRIM numbers are decor (≤ 24 px on screen, hidden when `pxPerBox < 40`). Must-read words go in the Stage hud at anchors.

### 2.4 Recurring motifs (identical everywhere)
1. **The passport photo** (`fictional-passport_a` on the desk and in the bin; `_b` on screen) and its file `passport.jpg`. It opens the film, dissolves into its bytes, returns in P21–P22.
2. **The Bit:** the photo's bytes are cyan Bits in their boxes, the only thing that is "the photo". Cyan threads run from its card to its boxes ("directions").
3. **The crossed-out card:** a coral strike across the photo's index card. The key image and the title line: "Delete crosses out the index card."

### 2.5 Colour roles
- **Cyan `#00E5FF`:** the photo's data (the Bit) and the card→box directions. Nothing else is cyan. The kit re-keys every inherited cyan default (Label/KineticText accents, type caret, QuestionCard underline, Prop highlight, Whip/ZoomThrough/Rewind accents, NightEnv dust, AtlasOpener stations) to `PAL.structure`/`PAL.ink`; the only exception is the AtlasOpener's travelling Bit, drawn as the photo's Bit. Cyan accents baked into renders (mft-record LEDs, trim-notice stripe, allocation-map tiles, ftl-map keys) are regraded to white or amber in the kit.
- **Amber:** energy and the drive's own action: housekeeping sweep, disposable tags, the drive actor / the chip, the sanitize pulse, the clock glyph, the encryption key.
- **Coral:** loss and danger: the strike-through, the free/unused tab, writes landing on the photo's boxes, refused writes, "Nothing left", the write tally.
- **Magenta:** emphasis only, sparingly: the TRIM note's tab, a QuestionCard "?", the LensDive ring, the one word to remember on a verdict.
- **Grounds:** the Signal Atlas navy family (`PAL`). Paper white `PAL.tile` for index cards and key caps. **Windows UI is dark:** window body #161D2B, title bar #1E2738, text `PAL.ink`, selection `PAL.structure` (never cyan).

## 4. Motion rules (hard)
- **Never static:** no stretch over **45 frames** without visible motion (every hold drifts 0.3–0.8 px/frame or pushes, plus secondary motion); no near-empty frame over **6 frames**.
- **Pacing:** a meaningful visual change every **3–6 s**; a **re-hook every 45–75 s** (§7).
- **Physical:** cards slide and click, boxes thunk, Bits pour and settle, the strike scratches, the TRIM note slides through its slot, the scanner beam sweeps, overwrites slam. Overshoot and settle on pops, ease-in-out camera, follow-through, motion blur on fast moves.
- **Sync:** events within ±3 frames of their word; labels hold ≥ 15 frames after their sentence ends. **Exception:** a section's last sentence gets no new must-read label in its final 30 frames; anything still up exits with the section's exit move. No label crosses a section boundary.
- **Transitions are motivated** (whip pans, lens dives, match cuts, object-to-diagram morphs, a literal rewind for "Restore"); never a cross-dissolve to empty. A cross-section whip is built in two halves: the outgoing section whips out over its last 6 f with blur, the incoming one whips in from the same direction over its first 6 f. Handoffs are fixed in §6.
- **Determinism:** no `Math.random`/`Date`; `random(seed)` from remotion.

## 5. Text rules (hard)
- Every text component has a **role**: hero 160–320 px · keyword 64–120 · label ≥ 40 · chip ≥ 40 · footnote 32 (≤ 6 words, not must-read, not counted) · decor ≤ 24 (box/TRIM numbers, UI chrome; never a claim or spoken word). Sizes are **on screen at 1080p**: the kit multiplies size × camera zoom × panel scale and logs `[kit] text below floor` / `[kit] world text without screen`. **Any [kit] text warning in a render log is a defect.**
- Use `screen` on Label/KineticText/Footnote in zoomed stages. Must-read words never sit inside `<Archive>` or a panel's scaled group; they go in the hud at anchors.
- ≤ 6 words per label; **≤ 12 must-read words on screen at once**, counting headers, chips, quotes and verdicts. The oldest label exits first.
- In half-scale frames, must-read capitals are ≥ 14 px tall and keyword capitals ≥ 22 px; check doubtful cases on a full-res still and its 390 px phone copy.
- Fonts: Sora (`SANS`), bold for numbers and keywords; `MONO` for box numbers, `passport.jpg` and the command line. "≠" always goes through `<Rich>` (the kit vectorises it).
- 64 px safe margin; the bottom 140 px free of must-read text. Keyword captions echo the voice and slam on the word; they are not subtitles.

- **Ownership:** sections `src/ep06/sections/S#.tsx` + `src/ep06/sections/S#/**` + `S#.cues.json` + `docs/ep06/plans/S#_plan.md`; kit `src/ep06/kit/**`. - **Section component:** `export const S#: React.FC<{frame:number}>` (absolute frame); renders any frame in [from−30, to+30], clamped.
- **Cloud render rules:** `export REMOTION_GL=angle` (software fallback on this VM; ≈ 2× faster than swangle and the owner's final-render backend). Every render/stills command holds the shared lock: `flock -w 480 /tmp/ep06-render.lock <command>` (on timeout, do other work and retry), or run it with the Bash tool's `run_in_background` and wait for the notification; never sleep-poll. One locked command renders at most **900 frames** (clip) or **48 stills**. Clips at `--scale 0.5 --concurrency 3`; stills `--concurrency 3`. Run `npx tsc` under `nice -n 10`.
- **Performance budget:** ≤ 0.6 s per frame per tab at `--scale 0.5 --concurrency 3`; one Stage per frame (transitions ≤ 18 f excepted); no SVG/CSS filters inside `<Archive>` (glow from shared gradients, bloom only from the Stage); ≤ 3,000 SVG nodes per Archive; ScrambleField = one `<text>` per box row; ≤ 4 distinct PNGs on screen; no backdrop-filter; the 16-drive row is code.
- **Sound cues:** `src/ep06/sections/S#.cues.json`, `[{frame, kind, strength}]`, kinds `whoosh | tick | pop | impact | riser | swell | dial | crate | sting | glitch | rewind | type` (crate = a box thunk, dial = a card flip or drawer slide, glitch = scramble, rewind = restore, type = keyboard). About 6–14 per minute; impacts only on hero beats.
- **Economy:** sheets, not dozens of single stills; ≤ 3 review rounds per section; no narration; final message ≤ 120 words.
